# 0.5.9 — Health endpoint alignment plan

**Design:** [`design-health-endpoints.md`](../notes/design-health-endpoints.md)
**Milestone:** 0.5.9 (internal; package version stays 0.5.8)
**Contains a breaking change:** `GET /health` no longer performs live model calls,
with no flag to restore the old behavior.

## Sequencing rationale

The packs are ordered so the repository is never in a state where the safe paths
are missing while the dangerous one is gone. H-1 lands the canonical surface
first; H-2 removes the hazard only once safe alternatives exist; H-3 makes
readiness meaningful; H-4 migrates callers; H-5 documents.

H-1 and H-3 both touch the same check-computation module, so H-3 follows H-1
rather than running beside it.

---

## H-1 — Canonical routes and `health+json` (additive)

**New:** `airlock/health_checks.py` — the check computations and payload builder,
kept separate from route registration so both are unit-testable without a
FastAPI app.

- `liveness_report()` → `pass` unless the process is wedged.
- `readiness_report()` → placeholder returning `pass` in this pack; H-3 fills it.
- `aggregate_report()` → liveness + readiness + model counts.
- `render(report)` → `(payload, http_status)`, `application/health+json`,
  200 for pass/warn and 503 for fail.

**Extend:** `airlock/health.py` — register `GET`/`HEAD` for `/livez`, `/readyz`,
`/healthz`, `/health/live`, `/health/ready` alongside the existing
`/health/circuits` installation, reusing its idempotence guard
(`app.state.airlock_*_installed`).

**Do not touch** `/health/liveliness`, `/health/liveness`, `/health/readiness`.

**Tests** (`tests/test_health_endpoints.py`): path/status/content-type matrix;
`HEAD` parity with `GET`; payload schema; legacy bodies unchanged byte for byte.

**Evidence:** all five new paths return 200 `application/health+json` against a
running proxy.

---

## H-2 — Replace `GET /health` (breaking)

**Extend:** `airlock/health.py` with `_replace_health_route(app)` per the design —
remove LiteLLM's `GET /health` from `app.router.routes`, then register Airlock's
returning the aggregate payload.

**Fail loudly** when the LiteLLM route is absent: raise at install time. A silent
no-op would leave the expensive endpoint serving while the changelog claims
otherwise, which is worse than a noisy startup.

**Update** `airlock/docs.py:250`, which special-cases `path == "/health"` for API
documentation enrichment, so the description matches the new semantics.

**Tests:** exactly one `GET /health` route after install and it is Airlock's;
installer raises on a synthetic app lacking the LiteLLM route; installer is
idempotent across double installation.

**The load-bearing test:** assert that no health path can trigger a model call —
patch the router/completion seam to fail the test if invoked, then exercise every
health path. This is the invariant the whole change exists to establish, and it
must be enforced by the suite rather than by review.

**Evidence:** `GET /health` returns in milliseconds; a JSONL diff across the call
shows zero new request records.

## H-3 — Meaningful readiness

**Implement** `readiness_report()` against cached `StateStore` state only:

| Condition | Status | HTTP |
|---|---|---|
| Router initialized, ≥1 model, ≥1 circuit closed | `pass` | 200 |
| Some circuits open, ≥1 closed | `warn` | 200 |
| No models configured, or all circuits open | `fail` | 503 |
| DB configured and unreachable | `fail` | 503 |
| No DB configured | `pass` with note | 200 |

Warn-not-fail on partial circuit-open is deliberate: pulling a pod from the load
balancer because one provider is rate-limited converts a partial outage into a
total one.

**Tests:** the full state matrix above, including the DB-absent case, driven
through a fake `StateStore` — no live calls.

## H-4 — Migrate internal consumers

Point Airlock's own probes at canonical paths, proving the new surface on the
first consumers to use it:

| File | Change |
|---|---|
| `airlock/cli/status_cmd.py:27` | `/health/liveliness` → `/livez` |
| `airlock/cli/dogfood_cmd.py:13` | `/health/liveliness` → `/livez` |
| `airlock/hooks/_common.py:48` | `/health/liveliness?client=` → `/livez?client=` |
| `airlock/tui/screens/overview.py:389` | `/health/liveliness` → `/livez` |
| `docker-compose.yml:15` | healthcheck → `/livez` |
| `deploy/k8s/deployment.yaml:46` | livenessProbe → `/livez` |
| `deploy/k8s/deployment.yaml:53` | readinessProbe → **`/readyz`** (currently points at a liveness endpoint) |

The k8s readiness change is a **correctness fix**, not a rename: routing traffic
to a pod that is up but not ready is exactly what readiness probes exist to
prevent.

**Compatibility:** these consumers parse the response body. `/livez` returns
`health+json`, not `"I'm alive!"`, so each call site's success check must be
updated to key off HTTP status or `status == "pass"` — not a string compare.
Existing tests (`test_cli_status`, `test_dogfood`, `test_cli_hooks`,
`test_mcp_manager`) will catch any missed site.

## H-5 — Documentation

- `docs/operations.md` — rewrite the probe table around canonical paths; add a
  copy-paste probe matrix for Kubernetes, Docker, and uptime checkers.
- `docs/troubleshooting.md:55` — replace the `curl /health` example.
- `docs/guide/vertex-batch.md:173` — the "do not probe `GET /health`" danger
  admonition becomes historical; state that `/health` is now safe and cheap.
- `docs/reference/` — document the `health+json` contract and status semantics.
- `CHANGELOG.md` — **breaking change** entry: `GET /health` no longer performs
  live model calls; deep results now come from background health checks read via
  `/health/latest`.
- Retire the repo hard constraint "never use `GET /health` for liveness probes"
  once H-2 lands — it becomes structurally true rather than a rule to remember.

## Out of scope

- Renaming or removing `/health/liveliness` and `/health/liveness`.
- Changing `/health/circuits`.
- Prometheus metrics or an OpenMetrics endpoint.
- Auth changes to any endpoint other than `/health`.

## Owner decisions — 2026-08-04

1. **No auth on any health endpoint for now.** Auth may later be required for
   variants that disclose more than liveness — anything enumerating providers or
   per-model state. Implementation must therefore keep the *disclosing* fields
   behind a single seam that can be gated later without reshaping the payload:
   probe endpoints return status and aggregate counts, and anything naming a
   provider or model stays in `/health/circuits` and `/health/latest` rather
   than migrating into the probe payloads.
2. **No external consumer probes `GET /health`.** The breaking change is
   therefore contained to this repository, and no migration window is needed.
