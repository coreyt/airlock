# Airlock 0.5.10 — Plan

**Theme: catch-up and clean-up.** Deliberately light on new features.

0.5.9 was oversized — a classifier subsystem, a breaking endpoint change, and
four closeout findings in one milestone. It also built backend capability that
nothing surfaces, deferred work with explicit obligations, and left issue
tracker entries that no longer match reality. 0.5.10 pays that down.

**Status:** planned, not started. 0.5.9 closed out at
`milestone/0.5.9-internal-closeout` (`b2752d7`), CI green.

**Publication:** to be decided at closeout. The package has been at 0.5.8 since
2026-08-02; 0.5.9 was an internal milestone with no version bump. Whether 0.5.10
is a PyPI release or another internal milestone is an **owner decision** and is
not assumed by this plan.

## What "catch-up" means here

Three distinct debts, in priority order:

1. **Capability with no surface.** 0.5.9 added semantic classifiers, bounded log
   queries, and health probes. An operator cannot see any of it in the TUI.
2. **Obligations recorded at 0.5.9 closeout.** Deferrals that were accepted with
   a stated reason, not dropped. They must land or be re-deferred deliberately.
3. **Drift.** Stale docs, superseded issues, deprecated stdlib calls, and
   suppressions with expiry conditions.

## A-2 — Deprecation and dead-code sweep

- **`datetime.utcnow()`** — 8 call sites in `airlock/slow/tuner.py` and
  `airlock/slow/analyzer.py`, deprecated and scheduled for removal. They produce
  most of the suite's warning noise. Replace with
  `datetime.now(timezone.utc)`. Careful: `utcnow()` returns a **naive** datetime
  and some call sites format it with a manual `"Z"` suffix, so a blind swap
  changes serialized output. Verify JSONL timestamp shape is unchanged — 0.5.9
  already had to fix legacy timestamp normalization once (`db76583`, `5003a6d`).
- **`advisor/tools._load_logs`** is now a thin shim over `_load_page`. Migrate
  the four remaining callers to `_load_page` so truncation state is not
  discarded, then delete the shim.
- **Warning budget:** consider `-W error::DeprecationWarning` for Airlock's own
  modules once the above is clean, so new deprecations fail rather than
  accumulate. Third-party warnings must stay non-fatal.

**Done when:** no `datetime.utcnow()` in `airlock/`, suite warning count
materially reduced, JSONL timestamp format proven unchanged by test.

## B-1 — TUI: semantic classifier visibility (#33)

0.5.9 records rich per-request classifier verdicts and ships
`airlock semantic-report`, but the TUI shows none of it. This is the clearest
case of capability with no surface.

Surface, reusing `airlock/semantic_report.py` rather than reimplementing
aggregation:

- per-classifier detection / clean / **unavailable** counts;
- tripwire category histogram;
- **`unavailable_reason` breakdown**, with `rate_limit` visually distinct — it
  is the attacker-inducible cause and it fails open, so an outage looks like
  quiet traffic;
- current mode (`observe`/`shadow`/`enforce`) and, separately, the **action**
  taken. `status` is the verdict; `action` is what Airlock did. The TUI must not
  conflate them, for the same reason the JSONL does not.

**Constraint:** the TUI stays off the hot path. Read JSONL through
`airlock/log_query.py`; never subscribe to the request event bus (see
`dev/plans/0.5.x-TUI-catchup-plan.md`).

## B-3 — MCP startup timeout, proxy side (#20)

**Partially delivered, and the delivered half is not the half the issue asks
about.** 0.5.9 added `startup_timeout` for **TUI-managed** servers
(`tui/mcp_manager.py`). The issue concerns LiteLLM's hardcoded 30-second
`anyio.fail_after(30.0)` around MCP tool listing at proxy startup: a slow stdio
server logs a warning and returns an **empty tool list**, which surfaces as
"the tools vanished" rather than as an error.

Investigate what Airlock can do without forking LiteLLM —
`AIRLOCK_MCP_STARTUP_MODE=lazy` already avoids the startup sweep, so the
remaining question is whether a slow server can be made to fail loudly instead
of silently. Prefer a diagnostic that names the server over a config knob that
hides the problem.

## C-1 — Advisory tool loop, Part B (F-1)

**Obligation recorded at 0.5.9 closeout.** The four advisory tools take no
arguments; they are fixed reveals of a precomputed payload. Part A (0.5.9) added
budgets and named stop reasons. Part B gives the tools real parameters — time
range, model, client, limit — validated against a strict schema and **served by
`airlock/log_query.py`**.

That dependency is the whole reason it waited: parameters without a bounded
reader would let a model request an arbitrarily large slice, which is exactly
what F-4 closed.

Truncation must reach the model. A tool result that silently omits records
invites confident conclusions about traffic the model never saw.

## C-2 — Auth and authorization for paid side services (#21)

Tavily (`tavily/web-search`), Perplexity (`perplexity-sonar*`), and NewsCatcher
(MCP server) consume paid credits. Tavily and Perplexity are ordinary model
entries, so they already sit behind `AIRLOCK_MASTER_KEY`; NewsCatcher is reached
through the MCP path.

**Scope this deliberately — it is the one pack that could grow into a feature
release.** Recommended bound for 0.5.10:

1. Establish and *document* the actual current posture per service (this is
   partly a documentation gap, not only a code gap).
2. Per-client authorization using machinery that already exists —
   `ClientIdentity`, the admission gate, and MCP tool policy — rather than new
   infrastructure.
3. Explicitly **defer** per-service quotas and billing attribution to the 0.6.x
   tenant-keys work, where budgets are already the theme.

If (2) cannot be done with existing seams, stop and re-scope rather than
building a parallel authorization system.

## Explicitly out of scope

- **Phase B indirect injection** (documents, MCP tool results). The largest
  security gap, needs provenance at the retrieval boundary, and is a design-first
  release of its own. Do not let it leak into a clean-up milestone.
- **F-3 code-inspection enforcement *by default*.** The plumbing exists and is
  operator-gated at weight `0.0`; raising that default needs its own observe
  window first, because `resource_access` matches any `open(` or `requests.` in a
  code block, i.e. ordinary code-assistance traffic. 0.5.10 corrects the docs
  that denied the plumbing existed; it does not change the default.
- **Multi-turn input boundary** (independent review finding #6).
- **#11 hybrid sparse+dense log search** — a feature.
- **0.6.x commercial-readiness line** — parallel track, own worktree, its own
  open DECIDE gate.
- Enabling Model Armor in production, or promoting semantic mode beyond
  `observe`. Both were settled at 0.5.9 closeout.

## Standing constraints

- Never probe a model from a health endpoint. A test enforces this; do not
  weaken it.
- The semantic tier's "unavailable is never clean" invariant is load-bearing.
- Probe payloads carry no model or provider names (unauthenticated endpoints).
- TUI stays off the request hot path.
- `config.local.yaml` and `dev/competitor-tracker.md` are owner-owned local
  artifacts — never commit them.
