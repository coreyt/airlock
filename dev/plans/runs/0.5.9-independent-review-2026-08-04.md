## The finding that mattered

#1/#5 was a genuine defect and an inconsistency the author missed. Provider
adapters sanitized their own exceptions to `transport_error:<Type>`, but
`run_classifiers._safe_run` stored `str(exc)` — and classifier results are copied
verbatim into request metadata and JSONL. A third-party classifier raising
`ValueError(f"bad response for prompt: {text[:200]}")` would have written user
prompt text into logs.

Worse, an existing test **asserted the leaky behavior** (`error == "boom"`), so
the suite was pinning the defect in place rather than catching it. Both that test
and `test_classifier_error_fail_open` were corrected.

Fix: `classifier_error:<ExceptionType>` in results, `error_type` in logs, matching
what the provider adapters already did.

## Accepted by design

**#4 — rate-limit fail-open.** Deliberate and configurable via
`AIRLOCK_SEMANTIC_ON_RATE_LIMIT`. Failing closed converts the bypass into a denial
of service, since the same flood then blocks every legitimate user. The upstream
control — capping per-client RPM at the admission gate so no single client can
exhaust the shared budget — is the real mitigation and is documented.

**#6 — latest-turn-only.** A real limitation, recorded rather than closed: an
attack seeded in turn 1 and triggered by a benign-looking turn 2 is not caught.
The reviewer's suggestion of an optional bounded multi-turn window is a
reasonable future option, off by default.
