# 0.5.8 enforcement design — independent local review

**Reviewer:** local second-persona adversarial review agent (read-only)

**Inputs:** the packet listed in
[`0.5.8-enforcement-design-review-protocol.md`](0.5.8-enforcement-design-review-protocol.md),

## Initial verdict: CONCERNS

The measurement and enforcement design is directionally sound, but it is not ready
for an enforcement PASS. The following four code-grounded findings must be resolved
with local tests before an enforcing patch is approved. None requires a provider call
or external review.

1. **P1 — P-2 measurement can be silently disabled. — RESOLVED**
   `normalize_reasoning_effort()` returns before `_warn_would_reject()` when
   `AIRLOCK_NORMALIZE_REASONING_EFFORT=0` (`airlock/reasoning_effort.py`). A zero
   report could therefore mean that no clients were affected *or* that the detector
   was off. Split measurement enablement from legacy translation, or emit a
   startup/config health witness and make report generation reject an unwitnessed
   period. Test that `env=0` preserves legacy request behavior while P-2 measurement
   remains visible, or that the missing witness prevents a report from passing.
   The implementation now scopes `AIRLOCK_NORMALIZE_REASONING_EFFORT=0` to only the
   legacy outbound mutation; `_warn_would_reject()` still runs, and
   `test_disabled_normalization_still_measures` pins the behavior.

2. **P1 — P-2b alternate selection is not score-correct. — RESOLVED**
   `_cross_tier_fuzzy_match()` keeps configured order and takes the first
   alternate-tier candidate. The design requires the highest-scored alternate-tier
   alias, with configured order only as tie-breaker. Sort by score descending with
   stable configured order for ties; add a three-or-more-candidate non-tie test and
   a cached-repeat assertion. Commit `81095d0` selects the highest numerical score
   and covers a three-candidate non-tie. Commit `f8b0f0e` then restores configured
   order for an equal score (`max` followed by the first matching candidate in the
   preserved scoring list) and `test_equal_score_alternate_preserves_config_order_and_cached_detail`
   uses reverse lexical/configuration order plus a cached repeat. The future enforcing
   suggestion is consequently stable with the current measurement diagnostic.

3. **P2 — P-2 capability support is over-inferred. — RESOLVED**
   `_supported_efforts()` unconditionally grants `low`, `medium`, and `high` to every
   dict returned by `litellm.get_model_info()`. A known OpenAI model without verified
   reasoning support can thus be under-measured and later accepted despite the design
   claiming capability-derived validation. Add a real reasoning-capability
   precondition or explicit verified level matrix, and fail open when it is absent.
   Test a model-info dict with no reasoning capability, explicit allowed/disallowed
   values, and an alias-to-body path through the runtime-shaped model list. The
   implementation now returns `None` (fail open) unless the map says
   `supports_reasoning is True`; `test_known_non_reasoning_model_fails_open` covers
   a known map record without that witness.

4. **P2 — queryability proof stops before the callback sink. — PARTIALLY RESOLVED**
   The current request-event test manually supplies a mutation; it does not exercise
   guardian/reasoning → recorder callback → enterprise/JSONL projection. Add a
   no-network integration test with a temporary log directory for both P-2 and P-2b.
   Assert the JSONL preserves marker, client id, and P-2b dimensions on success and
   failure paths, and that reporting rejects a malformed marker lacking those
   dimensions. Commit `81095d0` adds a useful P-2b chain from guardian →
   `RequestRecorderCallback` → `project_enterprise` → report
   (`tests/test_model_suggestion.py:84-139`) and a deterministic report/disposition
   tool. It still uses an in-memory lambda projection, not the enterprise sink's
   `record_event()` / `_write_log()` JSONL serialization path. It also covers only
   P-2b success, not P-2 reasoning-effort and not failure paths. Add no-network,
   temporary-log-dir tests that invoke the real recorder with `proxy_logger.record_event`,
   read the written JSONL via `iter_jsonl_records`, and feed it to the report for P-2
   and P-2b success/failure cases. Commit `f8b0f0e` now does this with the real
   `AirlockLogger.record_event` sink for all four P-2/P-2b × success/failure cases.
   It asserts the JSONL record's outcome, marker-derived report count, and client.
   **One assertion remains:** for P-2b the test does not assert the serialized report's
   `requested`, `served`, `suggested`, `from_tier`, and `to_tier` values. A missing
   structured metadata payload still counts as an event (with visible placeholder
   dimensions), so the current assertions would not catch a dimension-loss regression.
   Add those five exact assertions for both P-2b outcomes before PASS.

Minor documentation correction: the advisory mutation reason currently describes the
*emitted* value as unsupported. For `none → minimal` the emitted value is supported;
the reason should say the **requested** value is unsupported to avoid misleading the
operator report.

## What passed

- The direct OpenAI `max` probe now has a deterministic mocked wire-contract test and
  an explicit opt-in billable test. The mock verifies the probe; only the opt-in test
  can settle provider semantics.
- The review protocol names a separate local reviewer, fixed inputs, anchored
  questions, and PASS/CONCERNS/BLOCK rules. It needs no external data transmission.
- The design correctly treats P-2 and P-2b measurement windows as distinct and does
  not use the existing effort window as P-2b evidence.
