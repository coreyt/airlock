# 0.5.8 enforcement design — local review

## Scope

Reviewed `dev/notes/0.5.8-enforcement-design.md` against
`airlock/reasoning_effort.py`, `airlock/fast/model_alias.py`,
`airlock/fast/guardian.py`, `airlock/proxy_errors.py`,
`airlock/transparency.py`, the 0.5.8 plan, and the active reasoning-effort runbook.

## Findings resolved in the design

1. P-2b had no deployed `fuzzy_match_would_reject` event. The design now requires a
   standalone behavior-preserving measurement pack and a separate full-cycle window.
2. A cross-tier decision was under-specified. The design now defines one scoring pass,
   the `_TIER_AMBIGUITY_MARGIN` candidate set, stable tie-breaking, and fail-open
   behavior for missing tier data.
3. Event-sink delivery was claimed too strongly. It is now an explicit deployed
   queryability gate; code-level ledger propagation alone is insufficient evidence.
4. Existing Airlock catalogs are global. The design no longer claims per-client
   entitlement-safe suggestions that the current authorization model cannot provide.
5. `reasoning_effort=max` remains unresolved and requires a funded, authorized live
   call before P-2 enforcement.

## Verdict

**CONDITIONAL PASS (local source review).** The design is sufficient for the
non-mutating P-2b measurement seam and documents the blocks on enforcement. It is not
an independent review: an attempted external read-only review was disallowed because
it would transmit repository material. An independent review remains required before
any P-2 or P-2b enforcing patch is merged.
