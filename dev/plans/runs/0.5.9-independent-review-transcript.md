## Pass 1 — initial findings

Findings ordered per your priorities.

## 1) Correctness bugs

### 1. **Sensitive exception text is logged from classifier failures**
- **Severity:** high
- **File:** `airlock/guardrails/semantic.py` (`run_classifiers` → `_safe_run`)
- **What is wrong:** In `_safe_run`, when a classifier raises, you store `error=str(exc)` in `ClassifierResult`. That error is later copied into `metadata["airlock_semantic"]["results"][...]["error"]` and also logged in `async_moderation_hook`. This violates your own “safe metadata only” contract if any classifier exception embeds user text, headers, URLs, or provider body snippets.
- **Failure scenario:** A future provider adapter raises `ValueError(f"bad response for prompt: {text[:200]}")`. That text lands in request metadata/JSONL/logs.
- **Suggested fix:** Replace `str(exc)` with a sanitized code like `f"{type(exc).__name__}"` (or `classifier_error:<Type>`), mirroring what you already do in `ModelArmorProvider.inspect` (`transport_error:<Type>`). Keep full exception only in debug logs behind strict redaction, if at all.

### 2. **Provider builder failures can leak secrets in startup logs**
- **Severity:** medium
- **File:** `airlock/guardrails/providers/registry.py` (`build_providers`)
- **What is wrong:** `logger.error("... error=%s", exc)` logs raw exception text from builder failures.
- **Failure scenario:** Credential-loading error includes filesystem path or token-like content; this gets into operational logs.
- **Suggested fix:** Log exception type only (`type(exc).__name__`) or sanitize message. Keep verbose detail gated behind secure debug mode.

### 3. **Unbounded gather can stall classification if provider ignores timeout contract**
- **Severity:** medium
- **File:** `airlock/guardrails/prompt_injection.py` (`ProviderInjectionClassifier.classify`)
- **What is wrong:** `asyncio.gather` over providers has no outer timeout. You rely on each provider to self-timeout. If one adapter regresses and hangs, whole classifier can hang.
- **Failure scenario:** New provider forgets timeout; `during_call` guard task never resolves promptly, potentially affecting hook behavior/latency coupling.
- **Suggested fix:** Wrap each `_safe_inspect` call with `asyncio.wait_for(..., hard_timeout)` or wrap gather with a global cap and convert timeout to unavailable verdict.

## 2) Security bypasses / attacker control

### 4. **Rate-limit exhaustion is attacker-inducible and defaults to allow**
- **Severity:** medium (could be high depending on deployment)
- **File:** `airlock/guardrails/prompt_injection.py` (`_policy_for`, `classify_unavailable_reason`)
- **What is wrong:** You explicitly classify `local_rate_limit`/`http_429` as rate-limit and default policy effectively fail-open unless env overrides.
- **Failure scenario:** Attacker floods gateway to deplete classifier quota, then sends injection payloads while semantic layer returns unavailable/allow.
- **Suggested fix:** Operationally set `AIRLOCK_SEMANTIC_ON_RATE_LIMIT=block` in enforce-mode deployments, or add adaptive degradation (e.g., force tripwire-only block posture under sustained rate-limit failures).

(No code bug relative to your stated design, but this is an exploitable posture if default is left unchanged in production.)

## 3) Privacy leaks

### 5. **Classifier error strings are persisted into metadata**
- **Severity:** high
- **File:** `airlock/guardrails/semantic.py` (`async_moderation_hook` result serialization)
- **What is wrong:** `error: r.error` is emitted directly to metadata. Combined with finding #1, this is a direct privacy leak path.
- **Failure scenario:** Any classifier returns error containing provider response text or user excerpt; metadata retention leaks it.
- **Suggested fix:** Store structured error codes only (enum-like), never free text; redact before metadata write.

## 4) Input boundary (“latest user turn only”)

No critical correctness flaw in implementation of stated Phase A boundary; it matches design intent.

But one notable risk:

### 6. **Latest-turn-only misses delayed attack activation in earlier user turns**
- **Severity:** low (known tradeoff)
- **File:** `airlock/text_extract.py` (`extract_direct_input`)
- **What is wrong:** Only newest `user` message is classified; prior user content is assumed previously screened. This fails if policy/model/provider changed between turns, or if attack is split across turns where final turn is benign trigger.
- **Failure scenario:** Turn 1 seeds obfuscated jailbreak; turn 2 says “now apply previous encoding key.” Turn 2 alone may look clean.
- **Suggested fix:** Optional bounded context window mode (e.g., latest N user turns or latest+previous if token budget allows), disabled by default but available for higher-security deployments.

## 5) Test gaps

### 7. **No test ensuring semantic orchestrator does not leak raw exception messages**
- **Severity:** medium
- **File:** tests missing in `tests/test_semantic_mode_and_input.py` (or new file)
- **Gap:** You test provider adapter sanitization well, but not orchestrator-level exception sanitization.
- **Suggested test:** Register classifier that raises exception containing sentinel secret; assert sentinel is absent from `metadata["airlock_semantic"]` and logs (if log capture used).

### 8. **No hard-timeout test for misbehaving provider in aggregator**
- **Severity:** low
- **File:** tests missing in `tests/test_prompt_injection_providers.py`
- **Gap:** Assumes provider contract compliance. Need resilience test for a provider that never returns.
- **Suggested test:** Stub provider `inspect` awaiting never; verify classifier returns unavailable within orchestrator-imposed timeout (after implementing fix #3).

## 6) API/design issues

### 9. **Global mutable provider registry can be polluted across tests/runtime extensions**
- **Severity:** low
- **File:** `airlock/guardrails/providers/registry.py` (`register_builder`, `_BUILDERS`)
- **What is wrong:** `register_builder` mutates module-global map without reset API or namespacing.
- **Failure scenario:** Test/plugin registers override and forgets cleanup; subsequent builds use wrong builder silently.
- **Suggested fix:** Add reset/unregister helper (at least for tests), or freeze built-ins and separate extension registry.
