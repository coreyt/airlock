## What Airlock is

A policy and guardrail proxy wrapping LiteLLM. Requests pass through a chain:
PII redaction, keyword policy, an in-loop admission gate (per-client RPM +
concurrency), a fast guardian (threat scoring, circuit breaker, provider
quarantine), semantic classification, MCP tool policy, then post-call response
scanning, reasoning stripping, and PII rehydration. There is a Textual TUI, an
offline "slow" analyzer, and an advisor.

Shipped version is **0.5.8**. 0.5.9 was an internal milestone with no version
bump, so **everything 0.5.9 delivered is unpublished** — including a breaking
change (below).

## Repository conventions

- `uv` for everything: `uv run pytest`, `uv run ruff`, `uv lock --check`.
- Conventional commits. Bodies explain **why**, not just what.
- Evidence lives in `dev/plans/runs/`; corpora live in gitignored
  `data/corpora/`; reports must contain counts and identifiers, never prompt
  text.
- `config.local.yaml` (modified) and `dev/competitor-tracker.md` (untracked) are
  **owner-owned local artifacts**. They will show in `git status` on a clean
  checkout. Never commit them.
- `.env` and `secrets/` are gitignored and contain live credentials. Never read
  them into output, and never include them in any packet sent to a provider.

## Five things that will bite you if you do not know them

**1. `GET /health` changed, and it is a breaking change nobody has seen yet.**
It used to fire a live completion to every configured model. It is now a cheap
aggregate, with no flag to restore the old behavior. Canonical probes are
`/livez`, `/readyz`, `/healthz`. A test asserts that **no health path can reach a
model call** — do not weaken it; it is what converted a documented rule into a
structural one. Because 0.5.9 was never published, this lands publicly for the
first time whenever 0.5.10 ships. It must be prominent in release notes.

**2. "Unavailable is never clean."** The semantic classifier returns tri-state
verdicts: detected / clean / **no verdict**. A classifier that cannot answer is
never treated as clean and never counted as a vote in aggregation. This came
from a live reproduction: a misconfigured Google Model Armor template returns
HTTP 200 with an empty body, which a loose parser reads as "no match" — admitting
every request while looking perfectly healthy. If you touch that code, preserve
the invariant.

**3. `status` is the verdict; `action` is what Airlock did.** They differ in
every mode except `enforce`. Conflating them makes an observed detection look
like a blocked request. The JSONL, `airlock semantic-report`, and any TUI work
must keep them separate.

**4. Model Armor is disabled in production, deliberately.** No production prompt
text leaves the machine. Only the local tripwire runs, in `observe` mode. The
consequence, recorded at closeout: the semantic tier has **benchmark evidence
only**, not local false-positive evidence, so `shadow`/`enforce` are out of scope
for this deployment. Do not enable it or promote the mode.

**5. The TUI must stay off the request hot path.** It is a separate process that
reads JSONL and state files. Never subscribe it to the in-process request event
bus. Use `airlock/log_query.py` — the bounded reader — for any log reading you
add. Unbounded reads are what 0.5.9 finding F-4 fixed.

## Production safety

A **live** Airlock serves real clients from this working directory as a systemd
user service (`systemctl --user status airlock`), on port 4000.

- Do not restart it casually. A restart re-reads config from disk and applies
  every accumulated change at once.
- Verify MCP servers survive a restart: `config.yaml` must keep
  `include: ["config.local.yaml"]`, or MCP servers disappear.
- For experiments, copy the config to a separate directory and port.
- Liveness probes: `/livez`. Never `/health` for automation... though as of
  0.5.9 that is now safe, the habit is still worth keeping for the right reason:
  `/livez` answers the right question.

Known unrelated breakage: the local vLLM host `192.168.1.45:8000` is unreachable,
so `qwen3-32b`, `qwen3.6-27b`, `gemma-4`, `kimi-dev`, and `vllm/*` fail. That is
the machine, not Airlock. Do not chase it as a bug.

## What 0.5.10 is, in one paragraph

0.5.9 was oversized and left three debts: **capability with no surface** (a
classifier subsystem and bounded log queries that the TUI does not show),
**recorded obligations** (deferrals accepted with stated reasons), and **drift**
(stale docs, issues that no longer match the code, deprecated stdlib calls,
suppressions with expiry conditions). 0.5.10 pays those down and adds as little
new behavior as possible. If a pack starts growing into a feature, stop and
re-scope rather than letting it expand.

Suggested order: **A-1 → A-2 → A-3** first. They are small, independent, and A-1
in particular stops the issue tracker from actively misleading you. Then B-* and
C-*.

## Before you push

Run **every CI job locally first**. In 0.5.9 this caught a gating `pip-audit`
failure that would otherwise have failed the push:

```bash
uv lock --check
uv run ruff check airlock/ tests/
uv run ruff format --check airlock/ tests/
uv run mypy airlock/fast/ --ignore-missing-imports
uv run pytest -m "not live" -q
uv run mkdocs build --strict --site-dir /tmp/airlock-docs
uv run pytest tests/test_documentation_contract.py -q
uv run pip-audit --ignore-vuln PYSEC-2026-3552 --ignore-vuln PYSEC-2026-3553 --ignore-vuln PYSEC-2026-3554
docker build -t airlock:ci .
```

Those three `--ignore-vuln` flags are **conditional**. They cover `cryptography`
advisories that are unreachable in Airlock's usage and unfixable because
`litellm[proxy]` and `presidio-anonymizer` pin `<49`. Pack C-3 re-checks them:
run `pip-audit` **without** the flags, and if it passes, delete them and the
entry in `dev/notes/security-pip-audit-exceptions.md`.

## A habit worth copying from 0.5.9

Two of that milestone's most valuable findings came from **checking rather than
assuming**: an independent review found a privacy defect that an existing test
was *pinning in place*, and a local CI dry run found a gating failure before it
became a red build. Both were cheap. When a document tells you the state of
something, verify it — this note included.
