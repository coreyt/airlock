# 0.5.7 F-4 — enhanced provider cost investigation

## Step 1 finding

`EnhancedPassthroughProvider.acompletion()` returns the inner
`litellm.acompletion()` response unchanged. The inner request uses the physical,
priced target model and Airlock's `response_cost()` reads that response's
`_hidden_params["response_cost"]` directly. Therefore a populated inner cost
survives the Airlock provider boundary; no Airlock-side cost restamping is
required. The regression test for this finding also sends the returned response
through the fast monitor and verifies that Gemini provider spend receives the
same non-zero value.

This deliberately preserves LiteLLM's own target-model pricing, including any
long-context threshold pricing already calculated on the inner response. A
static outer-alias price would be less correct and would drift.

## Step 3 decisions

`tavily/web-search` remains a separate, deferred accounting question. It bills
per search credit rather than per token, and this investigation does not prove
that LiteLLM places a custom-provider `input_cost_per_request` in the callback
cost path. It needs a provider-specific, priced test before a flat rate is
configured.

The four self-hosted vLLM targets legitimately remain at $0.00. Airlock does
not yet distinguish an intentional self-hosted zero from an unknown external
price; an `airlock_unpriced`-style reporting marker is a future design item,
not part of this release.
