# 0.5.7 F-3 — refused-model suggestions

`ModelAliasTable.resolve()` returns `None` for both a deliberately refused
near-match and a genuinely unknown name. F-3 distinguishes them by calling
`suggest()` only after a failed resolution: a non-empty ranked list is an
actionable refusal, while an empty list remains LiteLLM's normal unknown-model
path.

Airlock currently has no client-specific model entitlement catalogue. The
configured model list is therefore the caller's catalogue, and suggestion
output is restricted to the aliases returned by that table. If a future
per-client catalogue is introduced, this filtering point must use it before
serializing the body or response header.
