# 0.5.7 F-2 — hard admission concurrency cap

The gate retains its synchronous RPM check. After it admits, guardian performs
a non-blocking slot acquisition under the gate's semaphore lock: it decrements
the semaphore value only when a slot is available, so it never queues an
`await sem.acquire()` waiter. A full semaphore turns the admission into the
existing F-1 shed response.

Guardian stamps the acquired client slot in request metadata. The response
header callback releases on both LiteLLM async success and failure callback
paths; it marks the metadata released before returning, making duplicate calls
idempotent. Any acquire/release exception logs and fails open rather than
breaking a request. The post-call response-header hook also attempts release,
covering paths that run it before the logger callback.
